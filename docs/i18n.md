# Languages and translations

ZacOS 9's own words are English in the source. A message catalog can put
them in another language, and the Numbers and Text control panels already
choose the locale's formats. This page is the rulebook for both; the
[catalog files](../po/) and `lib/i18n.c` are the implementation.

## What is translated, and what is not

Translated: labels, menus, alerts, hints, the installer's and login window's
words, and ZacOS Help. Not translated:

- **The protocol between programs and root helpers.** `shell/installer` reads
  `Error: ` and `step N`; `system/` helpers print them. Keep those English,
  and translate at the point they are shown.
- **Keys, paths, app IDs** (`desktop.conf`, `zacos9-controlpanel`, D-Bus
  names) and anything a program parses.
- **Other programs.** Firefox, LibreOffice and the rest have their own
  catalogs and use `LANG` already.
- **Product names.** Sniffer, Collar and Finder stay as they are; the words
  around them, including the control panels' own names, are translated.

The Control Panels folder and the Apple menu's Control Panels submenu read
their names from `share/applications/*.desktop`, so a panel's name is a
`Name[it]=` line there, not a gettext string; `lib/controlpanels.c` reads it
with `g_key_file_get_locale_string()`.

The menu bar's Hint Bubbles are found by the item's label (`hints.c`), so a
menu label and its row in the hint table must be translated together. The
`menu-hints-it` test checks that the Italian label still finds its hint.

## Marking a string

The message ID is the English text itself, so there are no invented keys.

```c
/* C, and a const char* in C++ */
panelText(c, _("Select a printer:"), M, LIST_TOP - 10);

/* C++ where a QString is wanted */
m_speed.add(tr9("Slow"), QPoint(M + IN, y));

/* A literal translated later, in a static table */
PANEL("mouse", N_("Mouse"), false, MousePanel);
```

`_()` is `zacos9_tr()`, `tr9()` is the QString version (`shell/common/tr.h`),
and `N_()` marks a literal without translating it there. Do not call the
C++ wrapper `tr()`: every `QWidget` already has `QObject::tr`, which wins
inside its member functions and quietly returns English.

Then add the file to [`po/POTFILES.in`](../po/POTFILES.in) and make the
template (it writes `po/zacos9.pot`):

```sh
meson compile -C build zacos9-pot
```

`po/LINGUAS` lists the languages that have a catalog, one per line. An empty
list is fine: no catalog installs, and every string stays English. A
translation is a `po/<lang>.po` beside it; `zacos9-update-po` merges a new
template into the existing catalogs.

Call `zacos9_i18n_init()` once in a program's `main`, after the locale is
set and before it makes windows. It sets `LC_MESSAGES` (not `LC_ALL`: the
Numbers panel's formats must not move) and points gettext at the catalog.

## Writing a translation

- Translate the `msgstr`, keep the `%1`/`%s` placeholders and their order can
  change. In C, never pass a translated string as a `printf` format: use
  `fputs()` or `%s`.
- Use `zacos9_trn()`/`tr9(singular, plural, n)` for counts. Do not build
  "1 item" by concatenation: Polish needs three forms, Japanese none.
- Never split a sentence around a value. `_("“%1” is on %2")`, not
  `_("“") + name + _("” is on ") + disk`.
- Length is part of the job. A panel is 360 px wide and cannot grow
  sideways; aim for the English length plus 30 %, and use the hint bubble
  for the long explanation. `panelWrap()` and `Text::inkWidth()` are there
  when a line can wrap.
- Keep the glossary: Sniffer, Collar, Control Strip, Control Panels, Get
  Info, Finder, alias. A term used two ways in one language is a bug report.

Catalogs are ordinary gettext: Poedit, Weblate or a text editor. Before
committing:

```sh
msgfmt --check --statistics -o /dev/null po/it.po
```

A partly translated catalog is safe to ship: gettext falls back to English
one string at a time. Better a reviewed 70 % than an unreviewed 100 %.

## Checking a layout

`ZACOS9_TEXT_STRICT=1` makes the text renderer print every string it had to
cut with an ellipsis:

```sh
ZACOS9_TEXT_STRICT=1 scripts/run-nested.sh
```

For the whole interface at once, use the pseudo-locale, which grows every
message by about a third:

```sh
meson compile -C build zacos9-pot
python3 tools/i18n/pseudo.py po/zacos9.pot /tmp/qqq.po
mkdir -p /tmp/qqq-locale/qqq/LC_MESSAGES
msgfmt -o /tmp/qqq-locale/qqq/LC_MESSAGES/zacos9.mo /tmp/qqq.po
LANGUAGE=qqq ZACOS9_LOCALEDIR=/tmp/qqq-locale scripts/run-nested.sh
```

`LANGUAGE` is ignored when the locale is `C`; run it in a session whose
`LANG` is a real locale (the Text panel makes one). The `i18n` test does the
same thing with a private locale, and also checks the truncation warning.

## Scripts and fonts

The interface is drawn with the bitmap faces in `assets/fonts`. They cover
Latin, with accents composed by `tools/fonts/build_fonts.py`; a character
they lack falls back to an outline face from Fontconfig: DejaVu Sans for
European scripts, Noto Sans CJK for Japanese. `fonts-noto-cjk` is a package
dependency and is in the ISO's package list.

| Script | State | Work |
|---|---|---|
| Western European Latin | Most accents exist; **ß œ æ ø þ « » ¿ ¡ are missing** | Add those glyphs to the `.pfont` masters. |
| Central European Latin | Missing (č ř ů ő ș ț ğ ı ł…) | Add the marks to `MARKS` and the few non-decomposable letters. |
| Greek, Cyrillic | DejaVu fallback is legible but not the same face; Russian is translated as a pilot | Glyph pass, language by language. |
| CJK | Display works through the Fontconfig fallback (Noto Sans CJK), with Unicode line breaking. **No IME**: ZacOS's own text fields do not accept composed input. | Translate, then add IME support before calling Japanese input complete. |
| Arabic, Hebrew, Indic | No shaping or bidi in the renderer | Not planned: the whole UI would need mirroring, not just the text. |

The Numbers and Text panel lists every UTF-8 locale because formats and
other programs use them; that list is not a promise that ZacOS 9's own
interface is translated into all of them.

## Russian

Russian uses the existing DejaVu Sans fallback: Cyrillic is legible but
not the bitmap face, and the system font is the same bold fallback as the
other scripts. No new font package is needed. `po/ru.po` is complete: all
817 extracted strings, including the Finder's dialogs, the control panels,
the menu bar and Hint Bubbles, the applications, the installer and the
Setup Assistant. `Name[ru]` is in 54 desktop entries; product names such as
Sniffer, Collar, Dog Ears, Pedigree, Photo Booth, Plotter, Stash, Retriever,
Scribble, Walkies, Bluetooth and TCP/IP stay as they are. The catalog
header declares Russian's three plural forms; no current string uses them
yet. The Keyboard panel already lists the Russian layout, and alphabetic Russian
needs no input method. The 20 help pages are in `share/zacos9/help/ru/`.
A native speaker should review the terms before the language is advertised.

## Japanese

Japanese is a display pilot, not a finished language. `po/ja.po` translates
the Mouse control panel, every control panel's name and window title, and
the Mouse desktop entry (`Name[ja]`), and leaves the other 777 strings
untranslated so they fall back to English one string at a time. The
rendering work is separate from translation:

- `lib/text.c` asks Fontconfig for the first face whose charset covers the
  code point. DejaVu Sans is tried first, so European text keeps its old
  look; kana and Han ask for a Japanese face and take `fonts-noto-cjk`.
  The chosen faces are cached per program, and a character no font covers
  still draws DejaVu's `.notdef` box.
- A session hides every installed font except the list in
  `share/fontconfig/zacos9-fonts.conf`; **Noto Sans CJK JP** is on that
  list, and in `fontMacFamilies()` so the Fonts folder agrees.
- `wrapText()` in `shell/common/pixels.h` wraps at Unicode line-break
  opportunities instead of spaces, so Japanese breaks between characters
  and keeps `。` and `、` off the start of a line. `panelWrap()` and
  `Alert` both use it. A run wider than the line is cut rather than allowed
  to overflow.
- The bitmap fonts' 12 px system and 11 px views line heights still apply.
  At 1x the pilot is readable; 1.5x and 1.75x are better for dense kanji.
  Choosing Japanese does not change the UI scale by itself.

**Input is not supported yet.** ZacOS's own text fields (`PanelEdit`, the
Finder's rename field and the installer's fields) handle key events
themselves and have no preedit or candidate window. A Japanese user can read
the interface but cannot type Japanese into it; Qt programs with ordinary Qt
text widgets can use an input method, but that is not enough. Do not
advertise Japanese as a usable language until that is built.

## What is still to do

Italian (`po/it.po`) now covers every control panel's name and window
title, the Mouse panel's own strings, the menu bar's menus and Hint Bubbles,
the Collar's module names, and the everyday applications' names and window
titles: Calculator, Notepad, Picture Viewer, Help Center, Software Update,
Disk Setup, Print Queue, Printer Picker, Setup Assistant, Theme Installer,
Windows Installer and the rest of the Applications folder. A native speaker
should review them before they are called complete.

Apps with a product name of their own (Dog Ears, Pedigree, Photo Booth,
Plotter, Stash, Terminal, XTerm) stay in English. Bark Recorder is
**Registratore** and Neighbourhood is **Vicinato**.

Japanese (`po/ja.po`) is the display pilot above: 38 strings in the Mouse
panel, every control panel's name and title, and the Mouse desktop entry.
A native speaker should review those terms, a panel with longer prose
should follow, and IME support is needed before Japanese input can be
offered.

Russian (`po/ru.po`) is complete at 817 strings, including the Finder's
dialogs, and all 20 help pages are under `share/zacos9/help/ru/`. A native
speaker should review the terms; the script needs no input method.

The installer now starts with a **Language** screen. It lists the UTF-8
locales by their own names and passes the choice to `zacos9-install
--locale`, which writes `/etc/default/locale` and `/etc/locale.conf` and
generates the locale on the target; the login window reads it. The
installer's own words are translated too: after Continue it restarts with
`LANGUAGE` set, so the Welcome, Select, Installing and Done screens follow
the catalog. The first screen stays English, because it must be readable
before a language is chosen.
The Setup Assistant is translated too, so a fresh Italian installation goes
from the installer through login and first-run setup in Italian.

The Finder's first slice is in: every alert's standard buttons (**OK**,
**Annulla**, **Non salvare**, **Salva**) through `Alert`, the core Finder
actions (Empty Trash, force quit, log out, search, eject/unmount, server
disconnection), the file-transfer and alias errors, and the Copying Files
window. The shared disk-plan strings in `plan.cpp` are translated too, so
Disk Setup and the installer's “next to what's on it” agree. The Finder has
many more messages; the rest follow a file at a time. View Options, its Preferences window, the Find window, Get Info (general,
Sharing and About This Computer), the Extensions Manager and the remaining
common Finder errors are in as well, and the Find criteria text is
translated. The Help viewer's UI and its Help Center/Search pages are
translated too.

Every Finder alert message is translated now, including encryption,
disk initialization, drag and drop, and the System Folder messages.

ZacOS Help overlays pages from `share/zacos9/help/<lang>/` on the English
tree: a translated page is used when it exists, and the English one stands
in when it doesn't. **The whole Italian and Russian help trees are in**:
all 15 ZacOS Help pages and all 5 tutorial pages under
`share/zacos9/help/it/` and `share/zacos9/help/ru/`. Next, in order:

1. The remaining product-named apps, if their names are to be translated.
2. A native speaker's review of the whole catalog and help.
